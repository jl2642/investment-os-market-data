# FMDL-7-0 — Master Plan, Authoritative Asset Registry & Acceptance Contract Freeze

## 1. Purpose

FMDL-7 is the final cross-market and full-system operating-acceptance program. It does not create a fourth market adapter, rebuild accepted FMDL-1 through FMDL-6 components, or use final acceptance to defer unresolved upstream defects.

FMDL-7 must prove that the accepted A-share, Hong Kong Stock Connect, US research-adapter and Investment OS operating bases can be recovered, reconciled, operated, monitored and independently accepted as one governed decision-support system while preserving market-specific evidence and authority boundaries.

## 2. Authoritative operating base

FMDL-7-0 binds seven machine-readable authoritative assets:

1. FMDL-1 A-share Current market-data and consumer interface;
2. FMDL-2 final history, factor, screening and stability pointer;
3. FMDL-3 final financial, valuation and incremental-evidence pointer;
4. FMDL-4 final Public Equity Investing and Investment OS integration pointer;
5. Investment OS Release 8 binary-canonical publication record;
6. FMDL-5 final Hong Kong Stock Connect immutable overlay pointer;
7. FMDL-6 final US research-adapter freeze pointer.

Every asset must exist, parse as JSON and match its frozen identity, status and `trade_authority = NONE` boundary. Chat memory is never an authoritative recovery source.

## 3. Authority separation

### GitHub

GitHub is authoritative for source code, schemas, workflows, machine contracts, immutable technical Releases, Manifests, Last-success pointers, LKG evidence and engineering history.

### File Library

After FMDL-7E, File Library is intended to hold the user-facing current operating package only:

- one current Canonical ZIP;
- one matching Pointer;
- one START_HERE.

Until FMDL-7E completes state reconciliation, clean-room restore and package verification, no claim is made that the FMDL-5 and FMDL-6 overlays have already been repacked into the File Library binary base.

### Investment OS Release 8

Release 8 remains the current binary Canonical base. It is not evidence that all later immutable cross-market overlays are already present inside the binary package.

## 4. Frozen seven-round program

### FMDL-7-0

Master Plan, Authoritative Asset Registry and Acceptance Contract Freeze.

### FMDL-7A

Cross-market Canonical Inventory and State Reconciliation.

Required scope includes the A-share, Hong Kong and US capability inventories; latest candidate, simulation and real-account state recovery; stale and coverage registries; and A/H/ADR duplication review. Research pools must not be relabelled as Candidate Pool membership.

### FMDL-7B

End-to-End Research and Decision Lineage Acceptance.

Replay representative A-share, Hong Kong and US cases from source evidence through factor/screening, Research Object, thesis, graduation decision and governed state route. No score-only graduation or automatic state admission is permitted.

### FMDL-7C

Portfolio, Simulation, Attribution and Rule Calibration Acceptance.

Reconcile observable real-account, simulation and candidate outcomes; separate facts, investment judgment, action recommendations and rule proposals; and keep every actual state or rule mutation behind explicit user authority.

### FMDL-7D

Scheduled Operations, Monitoring, Staleness and Cost Controls.

Validate Daily, Weekly, Monthly, Quarterly, Annual and Event-driven operating cycles through replay and controlled failure scenarios. Freeze monitoring, staleness, runtime and cost budgets.

### FMDL-7E

Failure Recovery, Clean-room Restore and Canonical Refresh.

Inject pointer, Manifest, stale-source, partial-publication and authority failures; prove LKG recovery; restore in a clean conversation without chat memory; then build and verify the next single user-facing Canonical package.

### FMDL-7-FINAL

Cross-market and Full-system Final Operational Acceptance.

Independently bind and validate the prior six stages, freeze the completed FMDL-0 through FMDL-7 development baseline and open only post-development operating observation.

## 5. Round and repair budget

The program is frozen at seven formal rounds and no more than two targeted repair rounds. Total FMDL-7 engineering rounds may not exceed nine.

A repair round is permitted only for:

- machine acceptance failure;
- authoritative Release or Pointer mismatch;
- invalid or unopenable Canonical package;
- unrecoverable current state;
- failed LKG or failure-recovery control;
- material state-authority breach;
- point-in-time or future-information leakage.

Writing preference, documentation polishing or discretionary scope expansion is not a repair trigger. FMDL-7F, FMDL-7G, FMDL-7X1, FMDL-7X2 and other unbounded subphase families are prohibited.

## 6. Canonical refresh boundary

The next user-facing single-package refresh is an FMDL-7E deliverable. It must not occur before FMDL-7A through FMDL-7D have accepted state, lineage, attribution and operating controls.

The final File Library posture is one current Canonical ZIP, one matching Pointer and one START_HERE, after user verification. GitHub retains all technical Releases and immutable evidence.

## 7. Authority and mutation boundary

FMDL-7-0 authorizes only plan freeze, authoritative-asset registration and future-stage gate freeze.

It does not authorize:

- new market-data refresh;
- research workflow execution;
- Candidate Pool mutation;
- simulation-book mutation;
- real-account mutation;
- CORE_STATIC or rule mutation;
- brokerage connection;
- order creation.

`trade_authority = NONE`.
